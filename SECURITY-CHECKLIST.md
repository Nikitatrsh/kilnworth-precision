# Pre-launch security checklist

Static site plus two serverless functions (`api/rfq.ts`, `api/upload.ts`) behind the quote form. No database, no login, no cookies, no third-party scripts. Data that does leave the visitor's browser: the form fields and uploaded files (stored in a private Vercel Blob store, sent as an email through Resend). First checked 2026-11-03 (static site); updated 2026-11-04 for the quote API.

| # | Item | Status | Notes and how it was checked |
|---|---|---|---|
| 1 | Hide API keys | OK | No keys in the repository. Keys are read from environment variables only (`server/config.ts`); `.env*` is in `.gitignore` except `.env.example`, which has names and no values. Checked 2026-11-04: `git grep` for `re_...`, `vercel_blob_rw_...`, `sk_live`, `AKIA`, private-key headers over all tracked files finds only documentation text; the browser bundle gets a short-lived upload token from the server, never the Blob token. |
| 2 | Purge git secrets | OK | Same patterns searched over the whole history (`git log -S`) and file list of every commit: no secret, no `.env` or `.local/` file was ever committed. |
| 3 | Public DB key only | N/A | No database. |
| 4 | Enable RLS | N/A | No database. |
| 5 | Encrypt sensitive data | OK | In transit: HTTPS (Vercel) with HSTS; uploads go to Blob over HTTPS. At rest: files are in a **private** Blob store (no public URL; the shop gets signed links that expire after 7 days). The server keeps nothing: a request lives in two emails. See README, "Decisions and known limits". |
| 6 | Server-side auth | N/A | No accounts or protected pages. The endpoints are public by design; they are protected by origin check, validation and rate limits (items 8, 11, 12). |
| 7 | Lock record access (IDOR) | N/A | No stored records and nothing is looked up by the request number. File URLs carry an unguessable random suffix, and the server only accepts URLs that point into its own private store (`server/adapters/storage-blob.ts`, tested with look-alike hosts). |
| 8 | Block field tampering | OK | `/api/rfq` builds its input from the known fields only (`server/validate.ts`); everything else is dropped (tested with `isAdmin`, `to`, `bcc`, `__proto__`). Select and checkbox values must be in the allowed lists; the browser's file sizes are ignored in favor of the size storage reports; the recipient of both emails comes from configuration or the validated email field. |
| 9 | Secure session cookies | N/A | No cookies at all. Two preferences in `localStorage` (`kp-unit`, `kp-demo-dismissed`), values checked against an allowlist in `public/boot.js`. |
| 10 | Hash passwords | N/A | No passwords. |
| 11 | Rate limit login | OK, with a limit | No login. The quote endpoints are limited per address: 5 accepted requests an hour and 60 calls of any kind to `/api/rfq`, 30 upload tokens an hour (`429` with `Retry-After`; tested). **Known limit:** the counter is in memory, per server instance, so on serverless the real limit is looser; move to Upstash or a Vercel Firewall rule before a client relies on it (README, SETUP-KEYS section 4). |
| 12 | Bot protection | OK | Hidden honeypot field `kp_extra`: a filled one gets the normal "ok" answer and nothing is sent (tested; also when the other fields are invalid, so a bot learns nothing). Origin check on every POST/PUT (missing or foreign origin gets 403). The rate limits above. No CAPTCHA (needs an account; owner's decision). |
| 13 | Parameterize queries | N/A | No database or queries. |
| 14 | Validate all input | OK | The browser checks for convenience; the server checks again against the same table (`src/lib/rfq-rules.ts`): required, lengths, ranges, whole numbers, pattern, allowed values, real calendar date, control characters, wrong types, 5-file and 25 MB limits, JSON body at most 32 KB (counted while reading, not from the header). The built form is compared with the table by a test, so the two cannot drift apart. About 215 tests including hostile values. |
| 15 | Escape user content | OK | Page: user input is written only with `textContent`/`createElement`; no `innerHTML`. Email: every visitor value goes through an HTML escape before it reaches the HTML part (tested with `<script>`, `<img onerror>`, quotes and `&`), subjects strip line breaks and direction-override characters, the Reply-To is a validated address. The only `set:html` is JSON-LD built from our own config, with `<` escaped. |
| 16 | Restrict file uploads | OK | Allowlist `.step .stp .iges .igs .dwg .dxf .pdf` on the last extension (`part.step.exe` is refused), 25 MB per file, 5 files, no empty files. Enforced in three places: the browser, the token request (name, extension, announced size) and the token itself (`maximumSizeInBytes`, random suffix, no overwrite, 30-minute life); then `/api/rfq` checks what actually arrived. **Content check:** PDF, STEP and DWG must start like their format; DXF and IGES must not be a program or archive (a program renamed to `.step` gets 415; tested). Files are stored privately and never served from our own origin. **Not covered:** no malware scan; rejected uploads stay in the store until cleaned by hand (README). |
| 17 | Trim API responses | OK | Responses contain only `ok`, the request number and per-field messages written for visitors. No stack traces, no internal messages (a failing mail provider or storage is logged as an error kind and answered with a generic text plus the shop's phone and email; tested). `Cache-Control: no-store` on all API answers. |
| 18 | Security headers | OK | `vercel.json`: CSP `default-src 'self'` with no `unsafe-inline` or `unsafe-eval`, `frame-ancestors 'none'`, `object-src 'none'`, `form-action 'self'`, `base-uri 'self'`; **`connect-src 'self' https://vercel.com/api/blob/`** (the only addition: the address the Blob SDK uploads to; the private store's read host is never contacted by the browser); HSTS (2 years, preload); `X-Frame-Options: DENY`; `X-Content-Type-Options: nosniff`; `Referrer-Policy: strict-origin-when-cross-origin`; `Permissions-Policy` denying camera, microphone, geolocation, payment, USB; `Cross-Origin-Opener-Policy: same-origin`; `Cache-Control: no-store` for `/api/*`. Verified with `npm run shoot -- --csp`: all 22 pages load under the real header with 0 violations (2026-11-04, after the change). **To confirm on the first deploy:** that a real upload is not blocked (README/SETUP-KEYS section 3, step 5). |
| 19 | Force HTTPS | OK (on deploy) | Vercel redirects HTTP to HTTPS by default; CSP adds `upgrade-insecure-requests`. Re-check with `curl -I http://<domain>` after the first deploy. |
| 20 | Scan dependencies | OK | `npm audit`: 0 vulnerabilities (2026-11-04). Runtime dependencies: `astro`, two font packages and `@vercel/blob` (official Vercel package). `@vercel/blob` pulled in a transitive version with a high `zod` advisory; `overrides` in `package.json` pins the fixed `@vercel/cli-config` (remove when the Blob SDK updates). Resend is called with `fetch`, no SDK. |

Exceptions to note:

- JSON-LD uses inline `<script type="application/ld+json">`. It is data, not executed, so `script-src 'self'` does not block it.
- In mock mode (no keys, local only) emails and files are written to `.local/`, which is ignored by git. On Vercel the API refuses to run without its keys instead of faking success (`ALLOW_MOCKS=1` overrides this for a throwaway preview).
- The quote form handles personal data (name, company, email, phone, drawings). `/privacy` must describe this accurately before the form is switched on (task D1).
